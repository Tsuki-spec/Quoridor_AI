# Quoridor 围墙棋

使用 Python、TensorFlow / Keras 和原生 HTML、CSS、JavaScript 实现的围墙棋实验。支持双人对战、人机对战、AI 观战，以及棋谱保存与回放。

## 安装与启动

已验证环境为 Linux / WSL2、Python 3.10、TensorFlow 2.21.0、Keras 3.12.4，支持 NVIDIA GPU。项目使用新版 TensorFlow，当前权重与代码按这一环境验证。

在项目目录安装依赖并启动：

```bash
python3 -m pip install -r requirements.txt
python3 app.py
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。服务地址与端口可在 [app.py](app.py) 的 `HOST`、`PORT` 中修改。

`requirements.txt` 列出主要依赖；`requirements-lock.txt` 记录已验证环境的完整依赖版本。需要复现该版本组合时，使用：

```bash
python3 -m pip install -r requirements-lock.txt
```

双人对战和无需模型的两种 AI 只依赖 NumPy，不会初始化 TensorFlow。仅使用这些功能时，可只安装 `numpy==1.26.4`。

GPU 训练需要系统提供兼容的 NVIDIA 驱动。Linux / WSL2 的 CUDA、cuDNN 用户态依赖由上述 Python 包安装。检查 TensorFlow 是否识别 GPU：

```bash
python3 -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))"
```

当前机器的 GPU 库路径已由终端启动配置设置；更换环境后，若库路径没有生效，可把已安装的 `site-packages/nvidia/*/lib` 目录加入 `LD_LIBRARY_PATH`。

## 网页使用

### 对战

- **双人对战**：双方在同一棋盘轮流操作。
- **人机对战**：选择算法、难度和先后手，再开始对局。AlphaZero 需要先在模型面板载入权重。
- **AI 观战**：分别设置双方算法、难度和模型文件，可进行新旧权重对比。支持暂停、继续、单步、悔棋和播放间隔调整。

选择走子、横墙或竖墙工具，再点击棋盘上的合法位置。设置在新对局生效；「重新开始」沿用当前对局的设置。重新载入权重后，需要新开对局才能使用新模型。

观战默认上限为 400 步，可设为 20～1000 步。思考中点击暂停，会在当前一步计算完成后停止；刷新页面会恢复对局并保持暂停，关闭页面后不会持续在后台计算。

### 棋谱

对局结束会自动保存到 `records/`；「保存棋谱」也可保存中途进度并下载 JSON 文件。

通过「历史棋谱」打开服务器记录，或用「导入回放」载入下载的文件。支持逐步查看、进度条与自动播放，回放结束后可返回原对局继续操作。

棋谱记录双方算法、难度、模型名称与 SHA256，以及动作、思考时间和结果。导入时会逐步检查动作合法性与胜者。文件格式为 `quoridor-record`、版本 1，最多 2 MiB、2000 步。

## 算法与难度

| 算法 | 是否需要权重 | 实现方式 |
| --- | --- | --- |
| Alpha-Beta | 否 | 迭代加深的 Negamax 与 Alpha-Beta 剪枝，使用路径距离、剩余墙数和跳跃机会评估局面。 |
| MCTS | 否 | UCT 搜索，结合路径先验、启发式 Minimax 估值和短程模拟，逐步扩大候选动作。 |
| AlphaZero | 是 | 策略价值残差网络引导 PUCT 搜索，使用搜索访问次数作为策略训练目标。 |

两种无需模型的 AI 使用以下预算，达到时间或搜索数量上限即停止：

| 难度 | 每步时间上限 | Alpha-Beta 深度 | MCTS 模拟次数 | 每节点候选墙数 |
| --- | --- | --- | --- | --- |
| 入门 | 0.15 秒 | 1 | 48 | 3 |
| 标准 | 0.6 秒 | 3 | 180 | 6 |
| 困难 | 1.8 秒 | 5 | 600 | 10 |
| 挑战 | 4 秒 | 7 | 1600 | 14 |

一层深度是一方的一次行动。Alpha-Beta 会保留上一层完整搜索的结果；候选墙筛选限制了搜索范围，因此不保证全动作树最优。

AlphaZero 的四档难度默认对应 64、128、256、512 次搜索，也可手动修改次数。它不使用上表的 CPU 时间上限，实际棋力取决于权重和搜索预算。

搜索会参考历史降低往返走子的优先级，分支遇到循环时停止展开。实际游戏不因重复局面自动判平局，训练和观战各自使用步数上限。

神经网络搜索复用墙布局的距离图，同时完成墙合法性检查和局面评估，减少重复寻路。它保留规则模块的完整合法动作集合；回归测试会比较两种检查方式的动作列表与搜索访问分布。

搜索会单独回传已证明的胜负，避免高访问次数掩盖已发现的败着。胜负证明来自终局与强制应手，网络的高置信度估值不作为证明。

叶节点还会估计两步攻防：选择自己的动作，再考虑对手的最佳回应。局部估值保留全部走子和按启发式排名靠前的 4 个放墙动作；对手的墙候选集中在双方路径附近。这种筛选只用于估值，PUCT 搜索仍保留完整的规则合法动作及强制应手检查。局部估值不用于证明胜负。

`TACTICAL_MIX = 0.5` 将两步估值与原来的网络、路径混合估值各占一半，设为 `0` 可关闭。网页和串行、多进程自对弈共用 [train.py](train.py) 中的设置。它增加 CPU 计算，相同模拟次数下也会比原版更慢。网络构建时关闭 TF32，以减少单局面推理和批量推理的数值差异；权重格式与网络结构不变。

### 网络与训练原理

[game.py](game.py) 提供七通道原始状态：双方棋子、两种墙、双方剩余墙数和行棋方向。网络自动补充双方到目标行的距离图，形成九通道输入；距离忽略棋子占位，与 `shortest_path_length` 的定义一致。

网络主干为 4 个残差块、64 通道，输出 209 个动作的策略 logits 和当前行棋方视角的价值值。价值头还直接读取双方距离与墙数，总参数为 347,808。旧七通道权重可以自动迁移，新连接补零以保留原预测。

自对弈记录 `(状态, 搜索策略, 价值目标)`，通过策略交叉熵与价值均方误差训练。PUCT 回传时逐层交换价值符号；训练搜索加入根节点噪声，探索不同走法。实现还混入路径启发与立即胜负检查，属于带领域知识的 AlphaZero 增强版本。

## 训练与续训

直接修改 [train.py](train.py) 顶部的变量，再运行，不使用命令行传参：

```bash
python3 train.py
```

主要参数的当前默认值：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `MODE` | `"train"` | 自对弈训练；改为 `"play"` 可在终端人机对战。 |
| `GAMES` | `1600` | 本次新增自对弈局数。 |
| `SELF_PLAY_WORKERS` | `16` | 自对弈进程数；设为 `1` 使用串行。 |
| `SIMULATIONS` | `400` | 每步搜索次数。 |
| `TACTICAL_MIX` | `0.5` | 叶节点两步攻防估值的混合比例，范围为 0～1。 |
| `UPDATES` | `8` | 每生成一局执行的梯度更新次数。 |
| `BATCH_SIZE` | `64` | 训练批量，样本不足时自动减小。 |
| `REPLAY_SIZE` | `20000` | 经验池最大样本数。 |
| `MAX_MOVES` | `400` | 双方行动的总步数上限。 |
| `LEARNING_RATE` | `0.0003` | Adam 学习率。 |
| `TEMPERATURE` / `LATE_TEMPERATURE` | `1.0` / `0.25` | 前 20 步与后续落子的采样温度，搜索策略目标保持温度 1。 |
| `RESUME` | `True` | 权重存在时载入后续训。 |

多进程模式由 CPU 子进程执行棋盘规则和搜索，主进程合并神经网络推理请求，并负责 GPU 训练与保存。它在一个终端内启动工作进程，无需分别打开多个终端。

默认保存路径为 `models/quoridor-resnet-b4-c64.weights.h5`，由 `MODEL_PATH` 指定。训练会持续更新该文件，另存实验模型时修改此变量。续训恢复网络权重，优化器状态和经验池重新初始化。没有现成权重时会从随机初始化开始训练。

真实胜负目标为当前玩家视角的 `+1` 或 `-1`。达到步数上限的对局按较弱的路径距离评分生成训练目标，受 `DISTANCE_VALUE_WEIGHT`、`DISTANCE_VALUE_SCALE`、`CURRENT_DISTANCE_MIX` 控制；它们不是规则模块中的胜负判定。

`MAX_MOVES` 按单方行动计数，双方各行动一次计两步。需要输出训练轨迹时，将 `TRACE_DIR` 改为目标目录。

## 随附模型

| 文件 | 用途 |
| --- | --- |
| `models/quoridor-resnet-b4-c64.weights.h5` | 当前默认的策略校准版。 |
| `models/archive/quoridor-critic-v5-b4-c64.weights.h5` | 校准前的原版，可用于回滚和对比。 |
| `models/archive/quoridor-strength-v3-b4-c64.weights.h5` | 较早的七通道版本，用于旧权重兼容性检查。 |
| `models/archive/quoridor-route-v4-b4-c64.weights.h5` | 对照候选，标准开局执后曾获胜。 |

原版权重使用 192 局教师对局与 559 个重新标注的局面校准价值头。当前权重由它进一步校准得到：保留残差主干和价值头，将最后的策略 Dense 层权重、偏置除以 2，使策略先验更平缓，给其他走法更多搜索机会。该变化已保存在默认权重中，无需修改搜索参数；它与自对弈落子采样的 `TEMPERATURE` 不同。

### 当前搜索的验证结果（2026-11-13）

本轮保持默认权重不变，改进叶节点的两步攻防估值。目标在观察最终对局结果前从 65% 降为 60%，即 60 局至少获胜 36 局。没有降低对手难度。

使用提前固定的 [holdout65_openings.json](tests/holdout65_openings.json)：30 个合法非终局开局，每个开局交换先后手，新旧搜索各 60 局。该组开局未参与本轮调参，并排除了旧测试集及已有评测棋谱中的相同起点；早期已丢弃的训练数据无法检查。双方使用相同的默认权重、FP32 精度、每步最多 128 次模拟、`c_puct = 1.5`、`prior_mix = 0.05`、`heuristic_mix = 0.15`、`repetition_penalty = 0.2`。对手仍为标准 Alpha-Beta（深度 3、每步最多 0.6 秒），步数上限为 200，包含预设开局。

| 搜索 | 胜 | 负 | 平 | 胜率 |
| --- | --- | --- | --- | --- |
| 旧版，不含两步攻防估值 | 28 | 32 | 0 | 46.7% |
| 当前版，`tactical_mix = 0.5` | 39 | 21 | 0 | 65% |

当前版达到下调后的目标；同组多赢 11 局，其中 14 个旧版败局转胜，3 个旧版胜局转败。执先为 17/30 胜，执后为 22/30 胜。120 局全部按规则重放检查了每个动作及最终胜负，原有 4 份权重和 13 份棋谱的哈希保持不变。

该胜率只描述这组固定开局与对手，不能保证对其他开局或真人的胜率。两种搜索的神经网络模拟预算相同，CPU 计算量不同：8 进程合并 GPU 推理时，单局总耗时中位数从约 26.3 秒增至 37.5 秒。这包含双方思考时间与并行调度，不能直接当作网页单步延迟。

开发集曾取得旧版 24/40 胜、新版 29/40 胜；它参与了候选筛选，不计入上述独立成绩。完整配置、代码摘要、候选源码、逐局动作见 [goal-65-final.json](records/goal-65-final.json)，结果和重放检查摘要见 [goal-60-summary.json](records/goal-60-summary.json)。两步估值已接入网页和自对弈；已有网页服务需要重启 `python3 app.py`，再新开对局。

另从标准初始棋盘通过真实网页 API 各测试一次先后手：对标准 Alpha-Beta 执先负（66 步）、执后胜（80 步）。两局棋谱均已保存并通过回放检查，搜索记录包含 `tactical_mix = 0.5`。这是功能检查，不计入上表；标准开局执先仍有弱点，不能把固定开局成绩理解为标准开局必胜。见 [goal-60-api.json](records/goal-60-api.json)。

### 历史权重对照（2026-11-11）

2026-11-11 的独立对照采用 [validation_openings.json](tests/validation_openings.json) 中的 20 个预设合法开局（前 6～16 步），每个开局交换先后手，每个模型共 40 局。筛选候选时没有使用这组对局结果。双方使用相同搜索实现，每步最多 128 次模拟，步数上限为 200，包含预设开局；对手为未经修改的标准 Alpha-Beta（深度 3、每步最多 0.6 秒）。

| 权重 | 胜 | 负 | 平 | 胜率 |
| --- | --- | --- | --- | --- |
| 原版 critic-v5 | 22 | 18 | 0 | 55% |
| 当前校准版 | 23 | 17 | 0 | 57.5% |

校准版在这组历史测试中多赢 1 局，提升幅度很小，不能据此认定有显著的普遍棋力提升。该结果不保证对其他开局、对手或真人也达到相同胜率。完整动作、双方模型 SHA256、搜索参数和逐局结果见 [model-evaluation.json](records/model-evaluation.json)。这组开局后来参与了新搜索的开发，不能继续作为新搜索的独立验证集。

另一个开发开局集用于筛选候选，校准版为 18/40 胜，原版为 17/40 胜；它与独立评测的开局、搜索版本不同，不混合计算胜率。大幅续训的候选没有通过对照，未替换默认模型。困难对手只作诊断，不作为本次达标门槛。

## 测试与评测

无需 GPU 或权重的 38 项回归测试，覆盖规则、两种经典搜索、AlphaZero 搜索、强制胜负回传、两步估值的视角与缓存、墙合法性缓存、固定评测开局、双进程自对弈、网页 API 和棋谱回放：

```bash
python3 -m unittest discover -s tests -v
```

检查真实模型的距离特征、旧权重迁移、单个与批量推理、保存载入和一次续训，需要默认权重及上一版备份：

```bash
python3 tests/verify_model.py
```

与标准 Alpha-Beta 交换先后手对战，并保存可回放棋谱：

```bash
python3 tests/evaluate_ai.py
```

在评测脚本顶部修改算法、难度、模型、搜索次数、`MAX_MOVES` 和可选的 `OPENING` 动作序列。结果摘要写入 `records/evaluation.json`，完整棋谱保存为同目录下的独立 JSON 文件。

将 `OPENINGS_FILE` 设为 `BASE_DIR / "tests/holdout65_openings.json"`，可对本轮固定的 30 个开局交换先后手对战，共 60 局。文件名保留最初的 65% 目标，最终验收目标已在观察结果前降为 60%。`validation_openings.json` 和 `arena_openings.json` 已用于开发，不作为新候选的独立验证。保持模型、搜索次数和对手难度一致再比较成绩；报告会记录模型 SHA256 和搜索代码摘要。对照原版权重时，将 `MODEL_PATH` 改为 `models/archive/quoridor-critic-v5-b4-c64.weights.h5`；若要单独比较本轮搜索改动，双方应使用相同权重，旧搜索设置 `tactical_mix = 0`。

本次独立对照使用 8 个进程合并 GPU 推理；此脚本通过网页 API 顺序运行，计时和推理批量不同，复测数字可能变化。

[tests/benchmark.py](tests/benchmark.py) 提供并行评测的 `run_arena(agents, openings, output, workers=8)`。每个 agent 配置包含 `weights`、`module` 和传给 `MCTS` 的 `search` 参数；由带 `if __name__ == "__main__":` 保护的 Python 脚本调用。它使用 CPU 子进程搜索、主进程批量 GPU 推理，逐局保存完整报告，并检查评测期间源码与权重没有变化。两种搜索使用同一个权重文件，旧版可设置 `tactical_mix = 0`，新版设置 `0.5`。

`OPPONENT_DIFFICULTY` 指定 Alpha-Beta 对手难度，默认 `"normal"`。改成 `"hard"` 可用深度 5、每步最多 1.8 秒的对手做更强的对照；不同难度的结果分别记录。

## 规则与动作编号

棋盘为 9×9，双方各有 10 堵墙。玩家 0 从上向下到达第 8 行，玩家 1 从下向上到达第 0 行，率先到达目标行任意格获胜。放墙不能重叠、交叉或切断任何一方的全部通路；相邻对手可直跳，直跳受阻时按规则斜跳。

| 动作编号 | 含义 |
| --- | --- |
| `0～80` | 走子到目标格，编号为 `row * 9 + col`。 |
| `81～144` | 横墙，编号为 `81 + row * 8 + col`。 |
| `145～208` | 竖墙，编号为 `145 + row * 8 + col`。 |

行列从 0 开始，墙坐标是其占据的 2×2 区域左上角。棋谱显示使用 A1～I9，横墙记作 `H:A1`，竖墙记作 `V:A1`。
